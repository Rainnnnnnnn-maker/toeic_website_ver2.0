# 今日の6語クイズ 仕様

最終更新日：2026-11-12

`/today-words/quiz` で、その日の「今日おすすめの6単語」の意味を4択で確認する機能。登録不要で、今日を含む直近7日分に挑戦できる。検討の経緯は [計画書](../../plans/TOEIC_今日の6語チャレンジ_実装イメージ_実現性評価.md) にある。

## 画面と導線

- **入口**：「今日おすすめの6単語」の枠にある「クイズ」ボタン（「聞き流し」の隣）。TOPと `/today-words` の両方に出る。
- **日付の切り替え**：今日を含む7日分のボタンが並ぶ。過去の日はクイズが保存されている日だけ表示し、「今日」は未生成でも表示する。今日の分が未生成のとき、最初はクイズのある最も新しい日を開き、「今日」を選ぶと「準備中」の案内を出す。
- **出題**：その日の6単語と同じ語・同じ順序。1問ずつ表示し、回答すると同じカードに正誤・例文・「詳しい解説を見る」を出す。
- **結果**：正解数と正答率、不正解の単語。不正解の単語は、押したときだけお気に入りへまとめて追加できる（`StudyBulkFavoriteButton`）。
- **単語詳細**：クイズから開いた詳細（`?from=quiz`）は「クイズに戻る」だけを表示し、前後の単語リンクを出さない。未回答の問題の単語を先に見られないようにするためで、`from=review` と同じ扱いである。
- ページは `noindex`。誤答はAIが生成し、人による確認を経ていないためである。

## 問題の作り方

1問は、正解1つと誤答3つで構成する。

| 部分 | 出どころ |
|---|---|
| 正解 | 出題語の `japaneseTranslation`。先頭の訳語と同じ語形の訳語を先頭から2つまで（`toQuizSourceWord`）。単語詳細ページと同じ内容で、文面は書き換えない |
| 例文 | 単語詳細の既存の例文（`pickExample`） |
| 誤答 | Gemini が生成する。使えない場合は、他の収録語の訳で代替する |

誤答は次の順で用意する（`src/data/daily-quiz.ts` の `ensureDailyQuiz`）。

1. **生成**：Gemini に6語をまとめて依頼し、1語につき候補を5つ作らせる。
2. **機械的な検証**（`filterAiDistractors`）：候補を1件ずつ確かめる。20文字以内で英字・括弧・「〜」が無いこと、訳語の数と語形が正解と同じこと、正解の訳（原文のすべての訳語）や他の候補と訳語が重ならないこと。
3. **確認**：通った候補を別の依頼で Gemini に見せ、「その単語の訳として成立してしまう候補」の番号を挙げさせる。訳語の文字列が重ならない近い意味（corp に対する「法人」など）は機械的には拾えないためである。
4. **採用**：残った候補の先頭3つを使う。3つに届かない語、確認の応答に含まれなかった語は代替へ回す。
5. **代替**（`buildFallbackDistractors`）：他の収録語の訳から、語形が同じで、類義語・派生語・訳語の重なりが無いものを選ぶ。Gemini の障害・利用上限・APIキー未設定のときは、6語すべてがこの方法になる。

モデルは `gemini-2.5-flash`（思考は無効）。`gemini-2.5-flash-lite` は正解の言い直し、同じ候補の繰り返し、訳語の数の無視が多く、検証を通る誤答をほとんど作れなかったため使わない。依頼は1日2回（生成と確認）である。

選択肢の並びは `日付:slug:文面` のハッシュ順で、同じ日・同じ語なら同じ並びになる。

## 生成の時刻と保存

- **契機**：既存の日次 Cron（UTC 22:05 = JST 7:05、`/api/revalidate/today-words`）。クイズを用意してから `today-recommended-words` タグを再検証する。ページの描画や利用者のリクエストでは Gemini を呼ばない。
- **その日の6語**：Cron の時点ではキャッシュ済みの「今日の6単語」がまだ前日の内容なので、単語リスト（`getAllWords()`）と `getTodayKey()` から計算する。
- **保存先**：Upstash Redis のキー `quiz:v1:<dateKey>`。保持は8日（解ける7日分より1日長い）。
- **再実行**：保存済みのクイズがその日の6語と一致していれば何もしない。Cron が再実行されても Gemini を呼び直さない。
- **失敗時**：クイズの生成に失敗しても、今日の6単語の切り替え（再検証）は必ず行う。応答の `quiz.status` に結果が入る。
- **全体の期限**：単語リスト・保存済みクイズ・単語詳細の取得、Gemini の2依頼、代替用の Redis 読み取り、保存までを通算して50秒で待機を打ち切る（`HTTP_TIMEOUT_MS.quizGeneration`）。ルートの `maxDuration` は60秒で、残り10秒を再検証と応答に確保する。期限切れは `quiz.status=failed` / `reason=timeout` を返す。Gemini にはキャンセルを伝え、共有キャッシュなどキャンセルできない取得が後から完了しても、次の取得やクイズ保存には進まない。

## 読み取りとキャッシュ

- `getRecentQuizzes()`（`src/data/daily-quiz.ts`）が Redis から7日分をまとめて読む。Cache Component で、タグは `today-recommended-words` と `word-list`。
- 「今日」は `getTodayRecommendedSelection()` の日付キーに合わせる。サイトに表示中の6語とクイズの6語が食い違わない。
- 当日分が揃っていれば `cacheLife('max')` で、翌朝の Cron まで保持する。当日分が欠けている間（生成前、生成失敗、Redis の一時的な障害）は `cacheLife('hours')` とし、1時間ごとに読み直して手作業なしで回復させる。
- Redis の値は `parseStoredDailyQuiz` で検証してから使う。当日分は表示中の6語と照合し（`quizMatchesWords`）、単語リストの更新で6語が変わっていれば出さない。
- `/words/[word]` から到達できる箇所では呼ばない。全単語ページが日次の再検証対象になるためである。

## 端末への保存

- 回答の進み具合は `localStorage` のキー `toeic-daily-quiz:v1`（固定の1つ）に持つ。日付ごとの回答と表示位置、利用者が選んだ日を保存する。
- 保存した回答はクイズの `generatedAt` と結び付ける。クイズを作り直した場合は最初からになる。
- 解ける期間から外れた日の回答は、次の操作時に捨てる。
- 「今日」はサーバーが渡した日付キーを使い、端末の時計からは計算しない。
- 端末を変えると引き継がれない。復習の進捗（`word_review_progress`）や連続学習日数（`learning_streaks`）は更新しない。

## 計測（GA4）

| イベント | 契機 | パラメータ |
|---|---|---|
| `quiz_start` | その日の1問目に回答 | `question_count`, `is_today` |
| `quiz_answer` | 回答のたび | `question_index`, `is_correct` |
| `quiz_complete` | 最後の問題に回答 | `correct_count`, `question_count`, `is_today` |
| `quiz_retry` | 「もう一度チャレンジ」 | `is_today` |
| `favorite_bulk_add`（既存） | 不正解の単語を1語以上追加 | `count`, `source=quiz_result` |
| `word_detail_open`（既存） | 「詳しい解説を見る」 | `word`, `source=quiz` |

出題語や選択肢の文面は送らない（`word_detail_open` の `word` は既存の仕様どおり slug を送る）。

## 運用

手動で実行する場合は、Cron と同じエンドポイントを使う。`<REVALIDATION_TOKEN>` は環境変数の値で置き換える。

```bash
curl "https://<your-site>/api/revalidate/today-words?token=<REVALIDATION_TOKEN>"
```

| クエリ | 動作 |
|---|---|
| なし | 今日の分が無ければ生成する。あれば何もしない |
| `quizDate=YYYY-MM-DD` | 直近7日以内の指定日の分を生成する。公開直後に過去の日を埋めるときに使う |
| `quiz=regenerate` | 保存済みでも作り直す。利用者の端末に残っているその日の回答は最初からになる |

応答の `quiz` は次のいずれかになる。

| `status` | 意味 |
|---|---|
| `generated` | 生成して保存した。`ai` はAIの誤答を使った問題数、`fallback` は代替の問題数、`skipped` は解説が無く出題できなかった語数 |
| `exists` | 保存済みのため何もしなかった |
| `failed` | 保存できなかった。`reason` に種類が入る（`rate-limit`、`timeout`、`upstream` など） |

当日のクイズが出ないときは、まずこのエンドポイントを手動で実行して `quiz.status` を確かめる。

## 既知の制限

- 誤答は人による確認を経ていない。確認の依頼も Gemini が行うため、正解として成立する誤答が残る可能性はある。
- 正解は訳語を2つまでに絞るため、TOEICで重要な語義が選択肢に出ないことがある（board は「板、掲示板」で「取締役会」が出ない）。
- 代替の誤答は意味の関連が薄い語になりやすく、AIの誤答より易しい。
- 公開した直後は、過去の日のクイズが無い。必要なら `quizDate` で埋める。
- 連続チャレンジ日数と結果の共有は未実装である。
