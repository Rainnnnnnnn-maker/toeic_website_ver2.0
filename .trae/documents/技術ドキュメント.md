# TOEIC重要単語（toeic_website_ver2.0）技術ドキュメント

最終更新日: 2026-07-26（依存脆弱性対応のレビュー修正：CI監査をfail-closed化し、お気に入りの認証世代分離とlocalStorage失敗時フォールバックを追加）

## 1. プロジェクト概要

### 1.1 目的と背景

* TOEIC頻出の重要単語を、一覧・検索・詳細表示（AI生成の解説）で効率良く学習できるWebアプリを提供する

* 単語の詳細解説は、外部AI（Google Gemini）で生成し、再利用可能なキャッシュ（Upstash Redis）でコストと待ち時間を削減する

* 発音確認のため、外部TTS（Google Cloud Text-to-Speech）で音声を生成する

* 単語学習モード（ランダム出題）で、学習のリズムを作る

### 1.3 システムアーキテクチャ概要図

```
ユーザー（ブラウザ）
  └─ 表示・操作
       └─ Next.js（App Router）
            ├─ ページ
            │    ├─ /        （トップ・一覧）
            │    ├─ /study   （学習モード）
            │    ├─ /favorites （お気に入り）
            │    ├─ /favorites/listen（お気に入り単語 聞き流しモード）
            │    ├─ /review    （復習モード）
            │    ├─ /today-words（今日おすすめ6単語）
            │    ├─ /today-words/listen（今日おすすめ6単語 聞き流しモード／Beta）
            │    ├─ /words   （全単語一覧インデックス）
            │    ├─ /words/[word]（単語詳細）
            │    ├─ /about, /privacy, /terms, /contact, /donate （静的ページ）
            │    └─ /guide, /guide/[slug] （学習ガイド一覧／個別記事 ─ SSG）
            │
            ├─ サーバ側データ取得（Server Component）
            │    └─ src/data/word-detail.ts:getWordDetail
            │         ├─ L1: Next.js Data Cache（"use cache" + cacheLife("max") + cacheTag(`word-detail-${slug}`, "word-detail")）
            │         ├─ L2: Upstash Redis（src/lib/wordCache.ts）
            │         └─ L3: Google Gemini で詳細JSON生成→正規化→Redis保存
            │    （Server Action `fetchWordDetail` は `src/actions/word.ts` に定義された `getWordDetail` の薄いラッパー）
            │
            ├─ 単語リスト取得（src/data/words.ts）
            │    └─ Vercel Blobから取得（Next.js Data Cache: cacheTag("word-list") + cacheLife("max")）
            │
            ├─ Proxy（src/proxy.ts）
            │    └─ 拡張子なしページルートのみを対象に、Server Actions以外のPOSTを405で遮断
            │       （現在はVercel Middlewareの利用量を削減するため、matcherを空にして無効化中）
            │
            └─ API（Route Handlers）
                 ├─ POST /api/tts
                 │    └─ Google Cloud Text-to-Speech を呼び出し、Base64音声(MP3)を返却
                 ├─ GET /api/revalidate/words
                 │    └─ Next.js Data Cache（word-list）を無効化し、最新の単語リストを再取得させる
                 ├─ GET /api/revalidate/word
                 │    └─ L1（Next.js Data Cache `word-detail-${slug}`）の特定単語キャッシュをクリア。upstash=trueパラメータでL2（Redis）もクリア可能。
                 ├─ GET /api/revalidate/upstash-word
                 │    └─ Upstash Redis（L2）の `word:<slug>` キーを削除（L1は触らない）
                 └─ GET /api/sitemap
                      └─ サイトマップ(XML)を動的生成して返却（`/sitemap.xml` から rewrite）。
```

## 2. 基本仕様

### 2.1 システム要件（ハードウェア/ソフトウェア）

#### 開発（ローカル）

* ソフトウェア: Node.js 20系、npm（`package-lock.json`に基づき `npm ci` を推奨）

* ハードウェア: Node.js/Next.jsの開発サーバが動作する一般的なPC

#### 本番（推奨）

* Vercel等のNext.js実行環境（リポジトリにはVercel用ワークフローが同梱）

### 2.2 動作環境条件

#### 必須の環境変数

`.env.example` に定義された以下を設定する（開発は `.env.local` を推奨）。

* `GEMINI_API_KEY`: Gemini APIキー

* `TTS_API_KEY`: Google Cloud Text-to-Speech APIキー

* `UPSTASH_REDIS_REST_URL`: Upstash Redis REST URL

* `UPSTASH_REDIS_REST_TOKEN`: Upstash Redis REST Token

* `WORD_CACHE_TTL_DAYS`: 単語詳細キャッシュTTL（日）。未設定時は30日

* `BLOB_READ_WRITE_TOKEN`: Vercel Blob（単語リストファイル取得）用のトークン

* `BLOB_URL_IMPORTANT`: 重要単語ファイルの直接URL（設定時、Vercelのlist操作をスキップ）

* `BLOB_URL_MEDIUM`: 中重要単語ファイルの直接URL（設定時、Vercelのlist操作をスキップ）

* `BLOB_URL_HIGH`: 高難易度単語ファイルの直接URL（設定時、Vercelのlist操作をスキップ）

* `REVALIDATION_TOKEN`: キャッシュ再検証API保護用のトークン（推測困難なランダム文字列推奨）

* `NEXT_PUBLIC_GA_ID`: Google Analytics 4 測定ID（G-XXXXXXXXXX）

* `NEXT_PUBLIC_SUPABASE_URL`: Supabase プロジェクト URL（任意ログイン + お気に入り同期）

* `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: Supabase Publishable キー（クライアント公開前提。データアクセスは RLS で保護）

#### 開発支援MCP用の環境変数（任意）

リポジトリ直下の `.mcp.json` をClaude Codeで利用する場合は、Claude Codeを起動する親シェルに以下を設定する。アプリ用の `.env.local` は親シェルへ自動exportされないため、MCP認証情報はシェル環境または安全なシークレット管理手段から渡す。

* `GITHUB_MCP_PAT`: GitHub MCPの認証用Personal Access Token。必要最小限のリポジトリ権限を付与する

* `UPSTASH_EMAIL`: Upstashアカウントのメールアドレス

* `UPSTASH_API_KEY`: UpstashアカウントAPIキー。リソース変更が不要な場合は読み取り専用キーを使用する

認証情報の実値は `.mcp.json` やその他のGit管理対象ファイルへ保存しない。

#### データ要件

* 単語一覧は Vercel Blob 上の `words-file/word.txt`（最重要単語: 600点レベル）、`words-file/word_mid.txt`（中級単語: 730〜800点レベル）、`words-file/word_high.txt`（高難易度単語: 800点以上レベル）の3ファイルをソースとして読み込む

  * 実装は `src/data/words.ts` でデータ取得を行う（`NODE_ENV=development` 時はローカルの `__words__/` 配下を読む）

  * 環境変数 `BLOB_URL_IMPORTANT`, `BLOB_URL_MEDIUM`, `BLOB_URL_HIGH` の3つがすべて設定されている場合は、`list` 操作を行わず指定URLから直接取得する（高速化・API節約）

  * 上記環境変数が未設定の場合は、`@vercel/blob` の `list` を用いてBlobから単語ファイルを取得する（`BLOB_READ_WRITE_TOKEN` が必要）

  * 取得結果は Next.js の `"use cache"` 指示により `cacheTag('word-list')` / `cacheLife('max')` 付きでキャッシュされる

  * Blob 取得の失敗（非 200 応答・fetch 例外・対象 Blob の欠損）は空配列で握りつぶさず例外を投げる。例外時はキャッシュに書き込まれず、バックグラウンド再検証の失敗時は直前の正常なキャッシュが使われ続けるため、「空の単語リストが長期キャッシュされて単語が消える」事故を防ぐ（ビルド時に Blob 取得が失敗した場合はビルド自体が失敗する）

  * `slug` は `term.toLowerCase()` で生成し、最重要/中級/高難易度を統合する際に同一slugは重複排除される（各単語は `level: 'important' | 'medium' | 'high'` を保持）

#### データ更新フロー

1. Vercel Blob 上の単語ファイルを更新・アップロードする
2. `GET /api/revalidate/words?token=...` を呼び出す
3. Next.js Data Cache が Stale（期限切れ）となり、次回のアクセスで最新データが再取得される

   * 環境変数 `BLOB_URL_*` 設定時: 直接URLへアクセス（list操作なし）

   * 環境変数未設定時: Blobの `list` 操作を行い、新しいURLを取得してアクセス

### 2.3 対応ブラウザ/デバイス

* 主要なモダンブラウザ（最新2世代を目安）

  * Chrome / Edge / Firefox / Safari

* PC/スマートフォンのWebブラウザ（レスポンシブはCSSで調整）

### 2.4 パフォーマンス指標

外部API（Gemini/TTS）の応答時間に強く依存するため、本項は「観測可能な指標」と「目標」を定義する。

#### 観測可能な指標

* キャッシュ階層

  * L1: Next.js Data Cache（`src/actions/word.ts` の `getWordDetail` が `cacheLife("max")` を指定）

  * L2: Upstash Redis（`src/lib/wordCache.ts` が `WORD_CACHE_TTL_DAYS` をTTLとして設定）

* 生成時の挙動

  * Redisが利用できない場合でも Gemini 生成は継続し、生成結果はRedisへ保存できない（ログに警告が出る）

#### 目標（運用基準）

* L1/L2キャッシュヒット時は体感的に即時（待ちを最小化）

* 生成（Gemini）に失敗した場合も、ユーザーが一覧へ戻れるUIを提供する

## 3. 技術詳細

### 3.1 採用技術の選定理由

* Next.js（App Router）

  * ページ/UIとAPI（Route Handlers）を同一リポジトリで管理でき、Vercelへのデプロイが容易

  * 静的生成/サーバ実行を用途に応じて使い分け可能

* Google Gemini（@google/genai の GoogleGenAI）

  * モデル: `gemini-2.5-flash-lite` を採用し、高速かつ安価に生成
  * TOEIC向けの「所定JSONスキーマ」で語義・例文等を生成する用途に適合

* Upstash Redis

  * サーバレス環境と相性が良いRESTベースのRedisで、生成結果を長期TTLで再利用可能

* Google Cloud Text-to-Speech

  * 発音音声をMP3で生成し、ブラウザで即再生できる
  * 高品質なニューラル音声（Neural2）やWaveNet音声を使用

### 3.2 主要なライブラリと依存関係

* `next`, `react`, `react-dom`: アプリ本体
* `tailwindcss`, `postcss`, `autoprefixer`: CSSフレームワークとビルドツール
* `@google/genai`（`GoogleGenAI`）: サーバ側データ取得（`src/data/word-detail.ts`）でGeminiを呼び出す
* `@upstash/redis`: サーバ側キャッシュ（`src/lib/upstash.ts`, `src/lib/wordCache.ts`）
* `@vercel/blob`: Vercel Blob から単語リストファイル（`words-file/word.txt`, `word_mid.txt`, `word_high.txt`）を取得する
* `@vercel/analytics`, `@vercel/speed-insights`: アクセス解析・パフォーマンス計測
* `@next/third-parties`: Google Analytics 4 (`<GoogleAnalytics>`) 組み込み用
* `lucide-react`: UI内で利用するアイコンコンポーネント
* `react-share`: SNSシェア機能の実装
* `server-only`: サーバーサイドコードの安全性確保
* `babel-plugin-react-compiler`: React Compilerによる自動メモ化（`next.config.ts` で `reactCompiler: true` を指定、`cacheComponents: true` も併用）

### 3.3 開発環境構築手順

1. 依存関係インストール

   * `npm ci`
2. 環境変数の設定

   * `.env.example` を参考に `.env.local` を作成し、各キーを設定
3. 単語データ配置

   * `./__words__/word.txt`（最重要）、`./__words__/word_mid.txt`（中級）、`./__words__/word_high.txt`（高難易度）が存在することを確認（1行1単語）
4. 開発サーバ起動

   * `npm run dev`
5. 動作確認

   * `http://localhost:3000` を開き、単語一覧→詳細→音声再生を確認

#### MCP開発支援（任意）

* `.mcp.json` はClaude Codeのプロジェクトスコープ設定として、次の4サーバーを定義する

  * `next-devtools`: 実行中のNext.js 16開発サーバーから、ルート・ログ・ランタイムエラー等を取得する
  * `playwright`: ブラウザ操作と手動スモークテストを支援する
  * `github`: GitHub APIをMCP経由で操作する（`GITHUB_MCP_PAT` が必要）
  * `upstash`: UpstashリソースをMCP経由で確認・操作する（`UPSTASH_EMAIL` / `UPSTASH_API_KEY` が必要）

* 認証が必要なMCPを使う場合は、Claude Codeの起動前に親シェルへ環境変数をexportする

  ```bash
  export GITHUB_MCP_PAT=<your-github-pat>
  export UPSTASH_EMAIL=<your-upstash-email>
  export UPSTASH_API_KEY=<your-upstash-api-key>
  claude
  ```

* Upstash MCPは現行CLI形式（`@upstash/mcp-server@latest --email ... --api-key ...`）で起動する。書き込み操作が不要な開発者は読み取り専用APIキーを使用する
* プロジェクトスコープのMCPサーバーは、Claude Codeの初回利用時に内容を確認して承認する

## 4. コンポーネント仕様

### 4.1 各コンポーネントの役割と機能

#### ページ/UI

* 主要画面の背景デザイン

  * TOP、全単語一覧、ログイン、お気に入り、今日のおすすめ、聞き流し、学習、復習は、視認性を高めた青系の放射グラデーションを使用する
  * 単語詳細は画面の識別性を保つためティール系を維持し、同様に背景濃度を上げる

* トップページ `src/app/page.tsx`

  * `Home` 本体は単語データ取得を直接 `await` せず、ページシェル・CTA・静的説明・学習ガイド導線を先に描画可能にする
  * 「今日おすすめの6単語」コンパクトセクション、最重要/中級/高難易度の単語一覧＋統計、FAQ/FAQPage JSON-LD はそれぞれ async Server Component に分離し、個別の `<Suspense>` 境界とスケルトン fallback でストリーミング表示する
  * 最重要/中級/高難易度の3レベルの単語を取得し、クライアント側一覧UIへ渡す
  * CTA直下に「今日おすすめの6単語」コンパクトセクションを表示する
  * SEO対策（「TOEIC重要単語」検索上位狙い）として、WebSite / BreadcrumbList / EducationalOrganization / FAQPage のJSON-LDおよび統計数値・選ばれる3つの理由・使い方ガイドを表示する
  * Google検索のサイト名候補だけを「TOEIC語彙ラボ」にする。対象は `WebSite.name`（初期サーバーHTMLへ直接出力）、`og:site_name`、Next.js `applicationName`。既存の上位表示を保護するため、SEOタイトル・description・H1・canonical・子ページタイトル末尾・publisher/author・PWA/OGP表記は従来の「TOEIC重要単語」を維持する。TOPの小ラベルとFooterでは「TOEIC語彙ラボ」と「TOEIC重要単語」を併記し、Googleのサイト名認識と既存キーワードの両方を補助する

* 全単語一覧インデックスページ `src/app/words/page.tsx`

  * 「TOEIC重要単語」検索上位獲得を目的とした全単語のハブページ
  * ファーストビューを学習ハブ化し、今日おすすめ6単語・暗記テスト・お気に入り・学習ガイドへの導線を配置する
  * 全1,300語超をレベル別（最重要/中級/高難易度）・アルファベット順に掲載する。完全索引は Server Component の通常 `<a href>` を維持したまま、ネイティブ `<details>` で「レベル → 頭文字」の二段階に折りたたみ、内部リンク構造とモバイルの一覧性を両立する
  * 目標スコア別の学習ポイントは一覧から分離したアコーディオンで表示し、検索結果への到達を妨げずに静的なSEO本文を維持する
  * metadata description の固定レベル別件数を廃止し、単語リスト更新後に件数が乖離しない「1,300語以上」表記へ変更する
  * パンくずリスト（BreadcrumbList）やアイテムリスト（ItemList）の構造化データを配置

* 今日おすすめ6単語ページ `src/app/today-words/page.tsx`

  * `getTodayRecommendedWords()` で選定済みの6語を取得し、「今日おすすめの6単語」表示コンポーネントへ渡す
  * 学習モード/トップへ戻る導線を提供する

* 今日おすすめ6単語UI `src/components/features/words/TodayRecommendedWordsClient.tsx`（Client Component）

  * Server側の `getTodayRecommendedWords()` で選定された6語のみを props で受け取る dumb component
  * 「聞き流し」リンクを併設し、`/today-words/listen` へ遷移できる
  * TOPのプレビューエリア・`/today-words` フルビューの両方で同一実装を使い、選定ロジックの単一ソース化を達成
  * 過去はクライアント側で全単語を再ソートしていたが、bundle 削減と「ホーム/聞き流しで選ばれる6単語の整合性」を担保するためサーバー側選定に統一済み

* 今日の単語 聞き流しページ `src/app/today-words/listen/page.tsx`

  * Server Component。`getTodayRecommendedWords()` で選定済みの6語を取得して `TodayWordsListenClient` に渡す

### 4.2 コンポーネント間の連携フロー

#### 単語詳細の取得（AI + 多段キャッシュ）

1. ブラウザが `/words/[word]` を開く
2. Server Component（`src/app/words/[word]/page.tsx`）が `getWordDetail(word)` を呼ぶ
3. `getWordDetail` は次の順に取得する

   * L1: Next.js Data Cache（ヒットすれば即返却）

   * L2: Upstash Redis（ヒットすれば即返却）

   * L3: Geminiで生成 → 正規化 → Redisへ保存 → 返却
4. クライアントはSSRされた `initialData` を描画する（`WordDetailClient`）

#### 今日おすすめ6語の選出

1. Server Component（TOP `/`、`/today-words`、`/today-words/listen`）が `getTodayRecommendedWords()` を呼び出す
2. `getTodayRecommendedWords` は `'use cache'` Cache Component。UTC日付キー + `slug` の FNV-1a ハッシュで安定ソートし、先頭6語を返却する。キャッシュは `cacheLife('max')` で長期保持し、毎日 JST 7:05 の Cron で明示的に再検証する
3. `TodayRecommendedWordsClient` は詳細リンクへ `from=today&today=<slug1,...,slug6>` を付与する
4. 単語詳細の `WordNavigation` は日次キャッシュを取得せず、`WordNavigationClient` がクエリ内のslugを `getAllWords()` の結果と照合して前後ナビを構成する。`today` クエリが欠落／全て無効な場合は全単語ナビにフォールバックする
5. `TodayWordsListenClient` は選定済みの6語を props で受け取るのみで、選定ロジックを持たない（単一ソース化）
6. 同一日内は同一セットになり、日付が変わるとセットが切り替わる

#### 聞き流しモードの再生フロー

1. ユーザーが「今日おすすめの6単語」エリアの「聞き流し(Beta)」ボタンから `/today-words/listen` に遷移
2. Server Component が `getTodayRecommendedWords()` で6語を取得し、`TodayWordsListenClient` に渡す
3. クライアントは現在語＋次の語の `WordDetails` を `fetchWordDetail`（Server Action）経由で prefetch（例文の即時表示用）
4. 再生ボタンで「単語 → 英語例文 → 日本語例文」の順に `fetchTTS` を呼び、Audio 要素で順次再生
5. 各遷移は `audio.onended` で発火し、ref 経由で「自分が現役か」を検査してから次のステップへ進む
6. 最終単語の最終ステップ完了で完了メッセージを表示し、再生ボタンで先頭から再開可能

#### 発音音声の生成（TTS）

1. クライアント（`useTTS`）が `POST /api/tts` に `{ "text": "word", "language": "en" }` を送信
2. サーバが Google Text-to-Speech API を呼び出し、`audioContent`（Base64）を取得
3. ブラウザが `data:audio/mp3;base64,...` として生成し、再生する

### 4.3 API仕様

#### 4.3.1 `POST /api/tts`

* 概要: 指定テキストの英語または日本語音声（MP3）を生成して返す

* ヘッダー:
  * `Content-Type: application/json`
  * `X-App-Source: toeic-client` （必須）

* リクエストボディ（JSON）

  * `text`: string（必須, 最大500文字）
  * `language`: "en" | "ja"（任意, デフォルト "en"）
  * `wordSlug`: string（任意。例文 TTS の場合は必須）

* セキュリティガード（順に評価）

  1. `X-App-Source: toeic-client` ヘッダーが必須
  2. `Origin` または `Referer` が `host` を含むこと
  3. `text.length <= 500`
  4. **Allowlist 検証**:
     * 単一英単語（空白を含まない英文）: `getWordBySlug(text.toLowerCase())` で語彙リストに存在することを確認
     * 例文（複数語、または日本語テキスト）: `wordSlug` を必須とし、Upstash Redis にキャッシュ済みの `WordDetails` を読み出して、`toeicExamples[].english/japanese` あるいは `meanings[].detailedMeanings[].example/exampleJapanese` のいずれかと完全一致（空白正規化後）すること。これにより、Referer 偽装攻撃に対する任意テキスト合成（コスト乗っ取り）を防止
  5. **レート制限**: Upstash Ratelimit による IP 単位 30 req/分（slidingWindow）。Redis にキャッシュ済みの結果を返す経路はカウンタを消費しない（cache miss のみ計上）

* キャッシュ階層

  * Redis 上の TTS キャッシュ（30日 TTL）。単一英単語は `tts:en:word:<slug>` キー、それ以外は `tts:<lang>:<wordSlugTag>:<sha256_12>` キー

* レスポンス（200）

  * `{ "audioContent": "<base64>" }`
  * `Cache-Control: public, max-age=86400`

* エラー

  * 400: `{ "error": "Invalid request body" }`
  * 400: `{ "error": "Text too long" }`
  * 400: `{ "error": "Word not allowed" }` — 単一英単語 allowlist に該当なし
  * 400: `{ "error": "wordSlug is required for example text" }` — 複数語または日本語テキストで `wordSlug` 未指定
  * 400: `{ "error": "Example text not allowed" }` — 例文テキストが語彙詳細の例文と一致しない
  * 403: `{ "error": "Unauthorized source" }` / `{ "error": "Unauthorized origin" }`
  * 429: `{ "error": "Too Many Requests" }` — レート制限超過。`Retry-After` / `X-RateLimit-*` ヘッダー付き
  * 500: `{ "error": "TTS_API_KEY is not configured" }` 等

#### 4.3.2 `GET /api/tts`

* 概要: 誤ったメソッド呼び出しに対するガード用エンドポイント

* レスポンス（405）

  * `{ "error": "Method Not Allowed", "message": "This endpoint requires a POST request with a JSON body containing the 'text' to synthesize." }`

#### 4.3.3 キャッシュ再検証 `GET /api/revalidate/words`

* 概要: 単語リストデータのNext.js Data Cache（`word-list`タグ）を無効化し、最新化を要求する

* クエリパラメータ

  * `token`: string（必須） - 環境変数 `REVALIDATION_TOKEN` と一致する値

* 動作

  * `revalidateTag('word-list', 'max')` を実行する

  * これにより、Data CacheはStale状態となり、次回アクセス時にバックグラウンドで最新データ（Blob）が再取得される（Stale-while-revalidate）

  * CDNキャッシュではなく、Next.jsサーバー内のData Cacheが対象

* レスポンス（200）

  * `{ "revalidated": true, "now": 1234567890 }`

* エラー

  * 401: `{ "message": "Invalid token" }`

#### 4.3.4 単語詳細キャッシュクリア `GET /api/revalidate/word`

* 概要: 特定の単語に対する L1 キャッシュ（Next.js Data Cache）をクリアする。オプションで L2 キャッシュ（Upstash Redis）もクリア可能。

* クエリパラメータ

  * `token`: string（必須） - 環境変数 `REVALIDATION_TOKEN` と一致する値
  * `slug`: string（必須） - キャッシュをクリアしたい単語（例: `additional`）
  * `upstash`: string（任意） - `true` を指定すると Upstash Redis のキャッシュも削除する

* 動作

  * `revalidateTag(\`word-detail-\${slug}\`, 'max')` を実行し、該当単語の L1 キャッシュをパージ
  * `upstash=true` の場合、`deleteWordDetails(slug)` により Redis からデータを削除

* レスポンス（200）

  * `{ "revalidated": true, "slug": "additional", "message": "Cache for word 'additional' has been cleared." }`

* エラー

  * 400: `{ "message": "Missing slug parameter" }`
  * 401: `{ "message": "Invalid token" }`
  * 500: `{ "message": "Failed to revalidate word", "error": "..." }`

#### 4.3.4.1 Upstash（L2）単語キー削除 `GET /api/revalidate/upstash-word`

* 概要: Upstash Redis（L2）に保存された単語詳細キャッシュ（`word:<slug>`）を削除する（Next.js Data Cache（L1）は触らない）

* クエリパラメータ

  * `token`: string（必須） - 環境変数 `REVALIDATION_TOKEN` と一致する値
  * `key`: string（必須） - `word:` で始まるRedisキー（例: `word:ability`）

* 動作

  * `key` から `slug` を抽出し、`deleteWordDetails(slug)` を実行して削除する（正規化後のキーは `wordCache.ts:cacheKeyForWord` と同一）

* レスポンス（200）

  * `{ "deleted": true, "key": "word:ability", "normalizedKey": "word:ability" }`

* エラー

  * 400: `{ "message": "Missing key parameter" }` / `{ "message": "Only word:* keys are allowed" }` / `{ "message": "Invalid key format" }`
  * 401: `{ "message": "Invalid token" }`
  * 500: `{ "message": "Failed to delete Upstash word key" }`

#### 4.3.5 サイトマップ生成 `GET /api/sitemap`

* 概要: サイト内の全ページ（静的ページ群および全単語詳細ページ）のURLを網羅した `sitemap.xml` を動的に生成する。
* 動作:
  * `next.config.ts` の `rewrites` 機能により、`/sitemap.xml` へのアクセスがこのAPIルートへルーティングされる。
  * 全単語一覧を `getAllWords()` で取得し、XML文字列を組み立てて返却する。
  * `Cache-Control` ヘッダーを用いてキャッシュされ、再生成の負荷を抑える。
  * **`noindex` ページ（`/favorites`・`/review`・`/login`・`*/listen`）は掲載しない**：sitemap に載せつつページ側で `noindex` を返すのは Google に矛盾したシグナルを送るため。
  * `lastmod` は静的ページ・ガイド記事（`article.updatedAt`）のみ出力する。**実更新日を管理していない URL（全単語詳細ページ、および日次ローテーションする `/today-words`）では `lastmod` を出力しない**：同一固定日を出すと Google が lastmod 自体を信用しなくなりクロール効率に悪影響が出るため、偽の日付を出すより省略する方針。`changefreq`/`priority` は残置しているが Google は無視する。

#### 4.3.6 サーバ側データ取得（`src/data/word-detail.ts` / `src/actions/word.ts`）

* 概要: 単語詳細（AI生成）を取得するためのサーバ関数群。ページ描画中（Server Component）に呼ばれる

* 関数

  * `getWordDetail(slug: string): Promise<WordDetails | null>`（`src/data/word-detail.ts`）: L1（Next.js Data Cache）でラップされた取得関数。Server Component から直接呼び出す
  * `fetchWordDetail(slug: string): Promise<WordDetails | null>`（`src/actions/word.ts`）: 上記を Server Action として公開（例外を握りつぶし `null` を返す）。学習モードのヒント取得などクライアントからの呼び出しに利用

* 返却

  * `null`: slugが単語リストに存在しない、または取得に失敗した場合

  * `WordDetails`: キャッシュまたは生成された詳細

* エラー

  * `GEMINI_API_KEY` 未設定時は例外を投げる（生成に失敗）

  * Upstash未設定/障害時も生成は継続するが、Redis読み書きは失敗する（ログに警告が出る）
