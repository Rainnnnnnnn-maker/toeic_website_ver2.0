# TOEIC重要単語（toeic_website_ver2.0）技術ドキュメント

最終更新日: 2026-04-16

## 1. プロジェクト概要

### 1.1 目的と背景

* TOEIC頻出の重要単語を、一覧・検索・詳細表示（AI生成の解説）で効率良く学習できるWebアプリを提供する

* 単語の詳細解説は、外部AI（Google Gemini）で生成し、再利用可能なキャッシュ（Upstash Redis）でコストと待ち時間を削減する

* 発音確認のため、外部TTS（Google Cloud Text-to-Speech）で音声を生成する

* 単語学習モード（ランダム出題）で、学習のリズムを作る

### 1.3 システムアーキテクチャ概要図

```
ユーザー（ブラウザ）
  └─ 表示・操作
       └─ Next.js（App Router）
            ├─ ページ
            │    ├─ /        （トップ・一覧）
            │    ├─ /study   （学習モード）
            │    ├─ /favorites （お気に入り）
            │    ├─ /review    （復習モード）
            │    ├─ /today-words（今日おすすめ5単語）
            │    ├─ /words   （全単語一覧インデックス）
            │    ├─ /words/[word]（単語詳細）
            │    └─ /about, /privacy, /terms, /contact （静的ページ）
            │
            ├─ サーバ側データ取得（Server Component）
            │    └─ src/data/word-detail.ts:getWordDetail
            │         ├─ L1: Next.js Data Cache（"use cache" + cacheLife("weeks") + cacheTag(`word-detail-${slug}`, "word-detail")）
            │         ├─ L2: Upstash Redis（src/lib/wordCache.ts）
            │         └─ L3: Google Gemini で詳細JSON生成→正規化→Redis保存
            │    （Server Action `fetchWordDetail` は `src/actions/word.ts` に定義された `getWordDetail` の薄いラッパー）
            │
            ├─ 単語リスト取得（src/data/words.ts）
            │    └─ Vercel Blobから取得（Next.js Data Cache: cacheTag("word-list") + cacheLife("weeks")）
            │
            └─ API（Route Handlers）
                 ├─ POST /api/tts
                 │    └─ Google Cloud Text-to-Speech を呼び出し、Base64音声(MP3)を返却
                 ├─ GET /api/revalidate/words
                 │    └─ Next.js Data Cache（word-list）を無効化し、最新の単語リストを再取得させる
                 ├─ GET /api/revalidate/word
                 │    └─ L1（Next.js Data Cache `word-detail-${slug}`）の特定単語キャッシュをクリア。upstash=trueパラメータでL2（Redis）もクリア可能。
                 └─ GET /api/sitemap
                      └─ サイトマップ(XML)を動的生成して返却（`/sitemap.xml` から rewrite）。
```

## 2. 基本仕様

### 2.1 システム要件（ハードウェア/ソフトウェア）

#### 開発（ローカル）

* ソフトウェア: Node.js 20系、npm（`package-lock.json`に基づき `npm ci` を推奨）

* ハードウェア: Node.js/Next.jsの開発サーバが動作する一般的なPC

#### 本番（推奨）

* Vercel等のNext.js実行環境（リポジトリにはVercel用ワークフローが同梱）

### 2.2 動作環境条件

#### 必須の環境変数

`.env.example` に定義された以下を設定する（開発は `.env.local` を推奨）。

* `GEMINI_API_KEY`: Gemini APIキー

* `TTS_API_KEY`: Google Cloud Text-to-Speech APIキー

* `UPSTASH_REDIS_REST_URL`: Upstash Redis REST URL

* `UPSTASH_REDIS_REST_TOKEN`: Upstash Redis REST Token

* `WORD_CACHE_TTL_DAYS`: 単語詳細キャッシュTTL（日）。未設定時は30日

* `BLOB_READ_WRITE_TOKEN`: Vercel Blob（単語リストファイル取得）用のトークン

* `BLOB_URL_IMPORTANT`: 重要単語ファイルの直接URL（設定時、Vercelのlist操作をスキップ）

* `BLOB_URL_MEDIUM`: 中重要単語ファイルの直接URL（設定時、Vercelのlist操作をスキップ）

* `BLOB_URL_HIGH`: 高難易度単語ファイルの直接URL（設定時、Vercelのlist操作をスキップ）

* `REVALIDATION_TOKEN`: キャッシュ再検証API保護用のトークン（推測困難なランダム文字列推奨）

* `NEXT_PUBLIC_GA_ID`: Google Analytics 4 測定ID（G-XXXXXXXXXX）

#### データ要件

* 単語一覧は Vercel Blob 上の `words-file/word.txt`（最重要単語: 600点レベル）、`words-file/word_mid.txt`（中級単語: 730〜800点レベル）、`words-file/word_high.txt`（高難易度単語: 800点以上レベル）の3ファイルをソースとして読み込む

  * 実装は `src/data/words.ts` でデータ取得を行う（`NODE_ENV=development` 時はローカルの `__doc__/` 配下を読む）

  * 環境変数 `BLOB_URL_IMPORTANT`, `BLOB_URL_MEDIUM`, `BLOB_URL_HIGH` の3つがすべて設定されている場合は、`list` 操作を行わず指定URLから直接取得する（高速化・API節約）

  * 上記環境変数が未設定の場合は、`@vercel/blob` の `list` を用いてBlobから単語ファイルを取得する（`BLOB_READ_WRITE_TOKEN` が必要）

  * 取得結果は Next.js の `"use cache"` 指示により `cacheTag('word-list')` / `cacheLife('weeks')` 付きでキャッシュされる

  * `slug` は `term.toLowerCase()` で生成し、最重要/中級/高難易度を統合する際に同一slugは重複排除される（各単語は `level: 'important' | 'medium' | 'high'` を保持）

#### データ更新フロー

1. Vercel Blob 上の単語ファイルを更新・アップロードする
2. `GET /api/revalidate/words?token=...` を呼び出す
3. Next.js Data Cache が Stale（期限切れ）となり、次回のアクセスで最新データが再取得される

   * 環境変数 `BLOB_URL_*` 設定時: 直接URLへアクセス（list操作なし）

   * 環境変数未設定時: Blobの `list` 操作を行い、新しいURLを取得してアクセス

### 2.3 対応ブラウザ/デバイス

* 主要なモダンブラウザ（最新2世代を目安）

  * Chrome / Edge / Firefox / Safari

* PC/スマートフォンのWebブラウザ（レスポンシブはCSSで調整）

### 2.4 パフォーマンス指標

外部API（Gemini/TTS）の応答時間に強く依存するため、本項は「観測可能な指標」と「目標」を定義する。

#### 観測可能な指標

* キャッシュ階層

  * L1: Next.js Data Cache（`src/actions/word.ts` の `getWordDetail` が `cacheLife("weeks")` を指定）

  * L2: Upstash Redis（`src/lib/wordCache.ts` が `WORD_CACHE_TTL_DAYS` をTTLとして設定）

* 生成時の挙動

  * Redisが利用できない場合でも Gemini 生成は継続し、生成結果はRedisへ保存できない（ログに警告が出る）

#### 目標（運用基準）

* L1/L2キャッシュヒット時は体感的に即時（待ちを最小化）

* 生成（Gemini）に失敗した場合も、ユーザーが一覧へ戻れるUIを提供する

## 3. 技術詳細

### 3.1 採用技術の選定理由

* Next.js（App Router）

  * ページ/UIとAPI（Route Handlers）を同一リポジトリで管理でき、Vercelへのデプロイが容易

  * 静的生成/サーバ実行を用途に応じて使い分け可能

* Google Gemini（@google/generative-ai）

  * モデル: `gemini-2.5-flash-lite` を採用し、高速かつ安価に生成
  * TOEIC向けの「所定JSONスキーマ」で語義・例文等を生成する用途に適合

* Upstash Redis

  * サーバレス環境と相性が良いRESTベースのRedisで、生成結果を長期TTLで再利用可能

* Google Cloud Text-to-Speech

  * 発音音声をMP3で生成し、ブラウザで即再生できる
  * 高品質なニューラル音声（Neural2）やWaveNet音声を使用

### 3.2 主要なライブラリと依存関係

* `next`, `react`, `react-dom`: アプリ本体
* `tailwindcss`, `postcss`, `autoprefixer`: CSSフレームワークとビルドツール
* `@google/generative-ai`: サーバ側データ取得（`src/data/word-detail.ts`）でGeminiを呼び出す
* `@upstash/redis`: サーバ側キャッシュ（`src/lib/upstash.ts`, `src/lib/wordCache.ts`）
* `@vercel/blob`: Vercel Blob から単語リストファイル（`words-file/word.txt`, `word_mid.txt`, `word_high.txt`）を取得する
* `@vercel/analytics`, `@vercel/speed-insights`: アクセス解析・パフォーマンス計測
* `@next/third-parties`: Google Analytics 4 (`<GoogleAnalytics>`) 組み込み用
* `lucide-react`: UI内で利用するアイコンコンポーネント
* `react-share`: SNSシェア機能の実装
* `server-only`: サーバーサイドコードの安全性確保
* `babel-plugin-react-compiler`: React Compilerによる自動メモ化（`next.config.ts` で `reactCompiler: true` を指定、`cacheComponents: true` も併用）

### 3.3 開発環境構築手順

1. 依存関係インストール

   * `npm ci`
2. 環境変数の設定

   * `.env.example` を参考に `.env.local` を作成し、各キーを設定

4. 開発サーバ起動

5. 動作確認

   * `http://localhost:3000` を開き、単語一覧→詳細→音声再生を確認

## 4. コンポーネント仕様

### 4.1 各コンポーネントの役割と機能

#### ページ/UI

* トップページ `src/app/page.tsx`

  * 最重要/中級/高難易度の3レベルの単語を取得し、クライアント側一覧UIへ渡す
  * CTA直下に「今日おすすめの5単語」コンパクトセクションを表示する
  * SEO対策（「TOEIC重要単語」検索上位狙い）として、WebSite / BreadcrumbList / EducationalOrganization / FAQPage のJSON-LDおよび統計数値・選ばれる3つの理由・使い方ガイドを表示する

* 全単語一覧インデックスページ `src/app/words/page.tsx`

  * 「TOEIC重要単語」検索上位獲得を目的とした全単語のハブページ
  * 全1,300語超をレベル別（最重要/中級/高難易度）・アルファベット順（先頭文字セクション）に一覧表示し、サイト内の内部リンク構造を最適化
  * 各レベルに「学習のポイント」ガイドを併設
  * パンくずリスト（BreadcrumbList）やアイテムリスト（ItemList）の構造化データを配置

* 今日おすすめ5単語ページ `src/app/today-words/page.tsx`

  * 全単語を取得し、「今日おすすめの5単語」表示コンポーネントへ渡す
  * 学習モード/トップへ戻る導線を提供する

* 今日おすすめ5単語UI `src/components/features/words/TodayRecommendedWordsClient.tsx`（Client Component）

  * UTC日付キー（`new Date().toISOString().slice(0, 10)`）と `slug` のハッシュで当日分の順位を決定する
  * 上位5語を表示し、TOPでも `/today-words` でも同一ロジックで表示する
  * TOPのプレビューエリアでは5語を全件表示し、各タイルから単語詳細へ遷移できる（専用の「すべて見る」ボタン導線は削除済み）

* 単語一覧UI `src/components/features/words/WordsListClient.tsx`（Client Component）

  * タブ切り替え（最重要/中級/高難易度の3タブ）、検索（前方一致＋ワイルドカード `*` 対応）、ページング（20件/ページ）
  * 検索結果表示時にはカテゴリバッジ（重要/中級/上級）を単語カードに表示する
  * 詳細ページへの遷移リンク（`/words/[slug]?from=top`等で状態を引き継ぐ）

* タブUI `src/components/common/TabNavigation.tsx`（Client Component）

  * 単語一覧のカテゴリ切り替えを提供する

* 単語詳細ページ `src/app/words/[word]/page.tsx`

  * Server Component内で `getWordDetail`（`src/data/word-detail.ts`）を呼び出し、初期データをSSRで配信する

  * データ取得は内部コンポーネント `WordDetailFetcher` に閉じ込め、`Suspense` で包むことでストリーミングレンダリング（スケルトン表示）を有効化

  * `generateStaticParams` で全単語をビルド時にSSG（Bot等のアクセスによるISR Function実行を削減）

  * Vercel Hobbyプランのビルドタイムアウト対策として `maxDuration = 60` を指定

  * 存在しない単語（`getWordBySlug` がヒットしない場合）は `notFound()` により404ページを表示する

  * 生成失敗時（`getWordDetail` が `null` を返す等）は、ページ内にエラーメッセージを表示する

  * `generateMetadata` 内でメタデータ（title, description, OGP, canonical）を動的に生成する

  * 単語別OGP画像 `src/app/words/[word]/opengraph-image.tsx`（Noto Sans JP 動的ロード）を配信

* 単語詳細UI `src/components/features/words/WordDetailClient.tsx`（Client Component）

  * Server Componentから渡された `initialData`, `linkedWords`（類義語の内部リンクマップ）, `relatedWords`（同レベル関連単語）, `level`（レベルバッジ表示）を描画する

  * 発音ボタンで `POST /api/tts` を呼び出し、返却されたBase64音声を再生（`useTTS` フック使用。単語再生・例文再生の両方対応）

  * お気に入り登録/解除の機能を提供する（`FavoritesContext`）

  * SNSシェアボタン（`SnsShareButtons`）を `ShareTargetContext` 経由で `createPortal` 表示

  * 学習アドバイス `StudyAdvice` コンポーネントを併設

* SNSシェア `src/components/features/sns/SnsShareButtons.tsx`

  * Twitter, Facebook, LINEへのシェア機能を提供する
  * シェア時にGA4イベントを送信する

* 単語詳細ヘッダ/前後ナビ `src/components/features/words/WordNavigation.tsx`（Server Component） / `WordNavigationClient.tsx`

  * 現在単語のパンくずと、前/次単語への遷移を提供する
  * クエリパラメータ `?from=top`, `?from=study`, `?from=review` を判定し、戻るボタンの遷移先や前後ナビゲーションの対象リスト（一覧、復習モードなど）を適切に切り替える

* お気に入り一覧 `src/app/favorites/page.tsx` / `src/components/features/favorites/FavoritesListClient.tsx`

  * 登録されたお気に入り単語を一覧表示する

  * `localStorage` に保存されたお気に入りデータを読み込む（`FavoritesContext` 経由）

  * 復習モードへの遷移ボタン（`ReviewModeButton`）を表示する

* 復習モード `src/app/review/page.tsx` / `src/components/features/review/ReviewWrapper.tsx`

  * お気に入り登録した単語をランダムに出題し、重点的に学習するモード

* 復習モードボタン `src/components/features/review/ReviewModeButton.tsx`（Client Component）

  * お気に入りページから復習モードへ遷移するためのボタンコンポーネント

* 学習モード `src/app/study/page.tsx` / `src/components/features/study/StudyClient.tsx`

  * ランダムに単語を提示し、「覚えている/覚えていない」の選択で学習を進める
  * カードの表裏を切り替えるUIと、カウントダウン表示によるリズム制御を行う
  * 「ヒントを見る」操作でAI詳細（`fetchWordDetail`）から例文を1件取得し、裏面に表示する
  * 学習状況は `sessionStorage` に保存し、戻る/進むでも継続しやすくする

* 静的ページ・法的文書 `src/app/(about|privacy|terms|contact)/page.tsx`
  * アプリの概要、プライバシーポリシー、利用規約、お問い合わせページを提供する
  * ユーザーの信頼性向上とSEO要件に対応

#### 共有/ユーティリティ/Hooks

* 単語データ `src/data/words.ts`

  * 開発時は `__doc__/word.txt`, `__doc__/word_mid.txt`, `__doc__/word_high.txt` を読み込み、本番は Vercel Blob から取得

  * `"use cache"` + `cacheTag('word-list')` + `cacheLife('weeks')` でデータキャッシュ（React の `cache()` でリクエスト内メモ化）

  * `getAllWords` / `getImportantWords` / `getMediumWords` / `getHighWords` / `getWordBySlug` / `getTodayRecommendedWords` を提供

  * `getRelatedWords` は `connection()` を使用して動的レンダリングを行い、`Math.random()` によりリクエスト毎に同レベルのランダムな関連単語を取得する機能を提供

* 単語詳細（AI生成＆多段キャッシュ）`src/data/word-detail.ts`

  * `getWordDetail(slug)`：`"use cache"` + `cacheTag(\`word-detail-\${slug}\`, 'word-detail')` + `cacheLife('weeks')` を付与したL1キャッシュ関数

  * 内部で L2（Redis） → L3（Gemini生成→正規化→Redis書き込み）の順で取得

  * Gemini応答のJSON抽出・トークン超過時の再試行（`maxOutputTokens` を 1024 → 2048 に段階的拡大）ロジックを持つ

* Upstash接続 `src/lib/upstash.ts`

  * 環境変数からRedisクライアントを初期化し、シングルトンとして利用

* 単語詳細キャッシュ `src/lib/wordCache.ts`

  * `word:<lowercased>` のキーで `WordDetails` をJSONとして保存/取得（`getWordDetails` / `setWordDetails` / `deleteWordDetails`）

* Server Actions `src/actions/word.ts`

  * `fetchWordDetail(slug)`：クライアントから呼び出すための Server Action。内部で `@/data/word-detail` の `getWordDetail` を呼び、失敗時は `null` を返す（学習モードのヒント表示などで利用）

* 型定義 `src/types/word.ts`

  * `WordDetails` 等の主要な型定義を管理する

* TTSフック `src/hooks/useTTS.ts`

### 4.2 コンポーネント間の連携フロー

#### 単語詳細の取得（AI + 多段キャッシュ）

1. ブラウザが `/words/[word]` を開く
2. Server Component（`src/app/words/[word]/page.tsx`）が `getWordDetail(word)` を呼ぶ
3. `getWordDetail` は次の順に取得する

   * L1: Next.js Data Cache（ヒットすれば即返却）

   * L2: Upstash Redis（ヒットすれば即返却）

   * L3: Geminiで生成 → 正規化 → Redisへ保存 → 返却
4. クライアントはSSRされた `initialData` を描画する（`WordDetailClient`）

#### 今日おすすめ5語の選出

1. TOP（`/`）または `/today-words` が全単語配列を `TodayRecommendedWordsClient` に渡す
2. `TodayRecommendedWordsClient` が UTC日付キーを生成する
3. `日付キー + slug` をハッシュして安定ソートし、先頭5語を採用する
4. 同一日内は同一セットになり、日付が変わるとセットが切り替わる

#### 発音音声の生成（TTS）

1. クライアント（`useTTS`）が `POST /api/tts` に `{ "text": "word", "language": "en" }` を送信
2. サーバが Google Text-to-Speech API を呼び出し、`audioContent`（Base64）を取得
3. ブラウザが `data:audio/mp3;base64,...` として生成し、再生する

### 4.3 API仕様

#### 4.3.1 `POST /api/tts`

* 概要: 指定テキストの英語音声（MP3）を生成して返す

* ヘッダー:
  * `Content-Type: application/json`
  * `X-App-Source: toeic-client` （必須）

* リクエストボディ（JSON）

  * `text`: string（必須, 最大500文字）
  * `language`: "en" | "ja"（任意, デフォルト "en"）

* レスポンス（200）

  * `{ "audioContent": "<base64>" }`

  * `Cache-Control: public, max-age=86400`

* エラー

  * 400: `{ "error": "Invalid request body" }`

  * 400: `{ "error": "Text too long" }`

  * 403: `{ "error": "Unauthorized source" }` / `{ "error": "Unauthorized origin" }`

  * 500: `{ "error": "TTS_API_KEY is not configured" }` 等

#### 4.3.2 `GET /api/tts`

* 概要: 誤ったメソッド呼び出しに対するガード用エンドポイント

* レスポンス（405）

  * `{ "error": "Method Not Allowed", "message": "This endpoint requires a POST request with a JSON body containing the 'text' to synthesize." }`

#### 4.3.3 キャッシュ再検証 `GET /api/revalidate/words`

* 概要: 単語リストデータのNext.js Data Cache（`word-list`タグ）を無効化し、最新化を要求する

* クエリパラメータ

  * `token`: string（必須） - 環境変数 `REVALIDATION_TOKEN` と一致する値

* 動作

  * `revalidateTag('word-list', 'max')` を実行する

  * これにより、Data CacheはStale状態となり、次回アクセス時にバックグラウンドで最新データ（Blob）が再取得される（Stale-while-revalidate）

  * CDNキャッシュではなく、Next.jsサーバー内のData Cacheが対象

* レスポンス（200）

  * `{ "revalidated": true, "now": 1234567890 }`

* エラー

  * 401: `{ "message": "Invalid token" }`

#### 4.3.4 単語詳細キャッシュクリア `GET /api/revalidate/word`

* 概要: 特定の単語に対する L1 キャッシュ（Next.js Data Cache）をクリアする。オプションで L2 キャッシュ（Upstash Redis）もクリア可能。

* クエリパラメータ

  * `token`: string（必須） - 環境変数 `REVALIDATION_TOKEN` と一致する値
  * `slug`: string（必須） - キャッシュをクリアしたい単語（例: `additional`）
  * `upstash`: string（任意） - `true` を指定すると Upstash Redis のキャッシュも削除する

* 動作

  * `revalidateTag(\`word-detail-\${slug}\`, 'max')` を実行し、該当単語の L1 キャッシュをパージ
  * `upstash=true` の場合、`deleteWordDetails(slug)` により Redis からデータを削除

* レスポンス（200）

  * `{ "revalidated": true, "slug": "additional", "message": "Cache for word 'additional' has been cleared." }`

* エラー

  * 400: `{ "message": "Missing slug parameter" }`
  * 401: `{ "message": "Invalid token" }`
  * 500: `{ "message": "Failed to revalidate word", "error": "..." }`

#### 4.3.5 サイトマップ生成 `GET /api/sitemap`

* 概要: サイト内の全ページ（静的ページ群および全単語詳細ページ）のURLを網羅した `sitemap.xml` を動的に生成する。
* 動作:
  * `next.config.ts` の `rewrites` 機能により、`/sitemap.xml` へのアクセスがこのAPIルートへルーティングされる。
  * 全単語一覧を `getAllWords()` で取得し、XML文字列を組み立てて返却する。
  * `Cache-Control` ヘッダーを用いてキャッシュされ、再生成の負荷を抑える。

#### 4.3.6 サーバ側データ取得（`src/data/word-detail.ts` / `src/actions/word.ts`）

* 概要: 単語詳細（AI生成）を取得するためのサーバ関数群。ページ描画中（Server Component）に呼ばれる

* 関数

  * `getWordDetail(slug: string): Promise<WordDetails | null>`（`src/data/word-detail.ts`）: L1（Next.js Data Cache）でラップされた取得関数。Server Component から直接呼び出す
  * `fetchWordDetail(slug: string): Promise<WordDetails | null>`（`src/actions/word.ts`）: 上記を Server Action として公開（例外を握りつぶし `null` を返す）。学習モードのヒント取得などクライアントからの呼び出しに利用

* 返却

  * `null`: slugが単語リストに存在しない、または取得に失敗した場合

  * `WordDetails`: キャッシュまたは生成された詳細

* エラー

  * `GEMINI_API_KEY` 未設定時は例外を投げる（生成に失敗）

  * Upstash未設定/障害時も生成は継続するが、Redis読み書きは失敗する（ログに警告が出る）

## 5. 開発ガイドライン

### 5.1 コーディング規約

* TypeScriptの `strict`を前提に実装する（`tsconfig.json`）

* Next.js App Routerの構造に従い、UIは `src/app/**` 配下に配置する

* import alias `@/*` を使用する（`@` は `src` を指す）

* Lintは `npm run lint` を必ず通す（`eslint-config-next` の推奨に準拠）

* React 18以降でのレンダリング中のRef更新（Ref mutation during render）によるエラー（`react-hooks/refs`）を防ぐため、レンダリング中に直前の値を保持して条件付き更新を行う場合は、`useState` を用いた派生ステートのアプローチを採用する

### 5.2 テスト方針（手動）

本プロジェクトのテストは手動を基本とする。

* トップページ

  * 一覧表示、タブ切り替え（最重要/中級/高難易度）、検索（前方一致＋ワイルドカード `*`）、ページングが期待通りに動作する
  * 「今日おすすめの5単語」プレビューが表示され、同一日内で同一単語が選ばれる

* 詳細ページ

  * 既知の単語は表示され、未知の単語はページ内エラー表示になる（現状）

  * 2回目以降のアクセスで表示が高速化する（L1/L2キャッシュの効果）

  * 発音ボタンで音声が再生される

* 学習モード

  * ランダム表示され、「覚えている/覚えていない」の導線が期待通りに動作する

  * 戻る/進むで学習状態が継続しやすい（`sessionStorage`）

* お気に入り機能

  * 単語詳細でお気に入りボタン（☆）を押すと登録/解除ができる

  * お気に入り一覧ページで登録した単語が表示される

  * ブラウザを閉じても保持される（localStorage）

* 復習モード

  * お気に入り単語のみを対象とした学習ができる

* SNSシェア

  * 詳細ページからTwitter/Facebook/LINEのシェア画面が開くこと

* エラー系

  * `GEMINI_API_KEY` 未設定で詳細生成が失敗し、詳細ページがエラー表示になる
  * `TTS_API_KEY` 未設定で `POST /api/tts` が500になる

* 静的ページ・SEO
  * `/about`, `/privacy`, `/terms`, `/contact` が正しく表示されること
  * `/sitemap.xml` にアクセスして全URLを含むXMLが返却されること

* データ更新

  * 単語データ更新後、Revalidation APIを叩いて最新データが反映されることを確認する
